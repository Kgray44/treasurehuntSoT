# Incremental evidence shadow lane

This lane retains observations and compares possible optimizations. It does not
authorize browser reuse, review credit, a release, or a protected merge.

## Capture and custody

The ordinary workflow input `incremental_evidence_shadow` defaults to `false`.
When explicitly enabled for capture, the protected producer runs after preparation,
parent cleanup, raw retention, and lifecycle retention. Its additional steps are
bounded. Handled unavailable observations return explicit data without credit;
step timeouts and opt-in publication failures fail the workflow. No step uses
`continue-on-error`. The existing Mainline Decision authority is unchanged.

The producer verifies its installed source, exact original run and candidate,
owner restrictions, parent closure, and provider artifact identities. Each runtime
joins its sibling profile receipt by the full diagnostic binding and declared
profile name. Input path order does not establish profile identity.

Closed journals retain original screenshot, trace, and recording IDs and hashes.
Accessibility and journey observations reference the original journal bytes;
cleanup observations reference the lifecycle member. Encrypted raw locations
explicitly identify their `index.encrypted` representation and original inner
path. Readable failed journals retain their local byte hash and an explicitly
unverified provider-member reference. Unreadable observations claim no immutable
location or verified custody. Neither receives completion credit.
An incomplete prefix cannot satisfy a complete manifest.

All production registry observations currently retain
`UNATTESTED_SHARED_TASK_RUNTIME`. Unknown source, conditional coverage, runtime,
or dependency facts require fresh work. Hashes and declarations do not certify
external runtime isolation. Capture diagnostics on installed main carry the
distinct `capture-diagnostic` producer mode and cannot be relabeled ordinary
candidate evidence.

## Provider and owner joins

`authenticateNativeOriginalContext` reads fixed provider endpoints, original
early-step logs, and exact producer/reader source. It ignores mutable PR
associations as original source authority. Successful and failed observations
retain bounded original response bytes through an opaque handle.

`authenticateNativeRegistryArchive` additionally requires the original capture
proof, unchanged control-plane source, sealing and upload steps, matching provider
metadata, exact archive size and digest, and a bounded single-member ZIP.

`openNativeRegistryRetention` requires that opaque transport proof, independently
expected coverage, original spent review ordinals, and the existing owner's
private key supplied in memory. It offers no key discovery, alternate public-key
policy, key provisioning, or CI private-key transport. It preserves original
candidate identities, artifacts, review ordinals, and findings. Its result still
grants no reuse or qualification.

## Context and dependency experiments

The dependency graph and preservation planner compare complete source closures,
including deletion and reverse dependencies. Unknown facts remain fresh. The
current import recognizer is conservative shadow instrumentation, not an
activation certificate.

The optional single-context worker uses the existing process supervisor. An owned
application and capture process must close before SQLite online backup and
private cookie-cache retention. Opaque in-process capabilities bind actual child
creation and closure to the stored cut. Serialized receipts cannot recreate them.
The prefix comparison restores SQLite, fixture state and private cookies while
preserving earlier artifact IDs. Partial capture output is rejected by ordinary
experience acceptance.

Limits include 128 contexts, 8,192 registry artifacts, a 2 MiB manifest, an 8 MiB
encrypted registry envelope, a 9 MiB provider registry ZIP, 64 MiB per retained
media file and 256 MiB aggregate media verification. Snapshot chunks have a
separate 64 MiB aggregate bound. Exceeding a limit cannot silently grant partial
coverage or increase a legacy limit.

The V2 completed-obligation codec compacts duplicate JSON frames without changing
any restored bytes, immutable identities, failed receipts, or review ordinals.
Legacy V1 admission and its limits remain separate. A codec result is not an
authenticated receipt.

## Activation boundary

These mechanisms require independent equivalence and adversarial review before
activation. Synthetic fixture transport and keys test local boundaries; they are
not native provider certification. After protected installation, an explicitly
requested installed-source native capture must validate the real provider and
owner-key route. External isolation, coverage and review obligations still apply.
