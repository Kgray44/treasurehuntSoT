# Darwin audit-token signal primitive feasibility

This separate prerequisite supports the existing Sextant Phase 4 continuation.
The previous task-port termination probe and its five original evidence files
remain immutable. Do not repeat that rejected primitive, install a guardian or
modify production cleanup, iOS Devices, account or signing behavior.

Use only the fixed `darwin-audit-signal` development target on one ephemeral
GitHub-hosted macOS runner. Candidate/closure tiers and scenario/profile overrides
must fail before any external operation. The `all` target must not select this
experimental job. Obtain independent source review before its first dispatch.

The C probe creates exactly three finite known direct children. All have their own
five-second alarm and four-second natural exit. A parent alarm bounds the whole
observer. Root use is restricted to hosted CI and installation inside a newly
created private temporary directory. No account is created; the currently absent
numeric UID is not an exclusive lease.

After readiness, expected-image and real/effective/saved credentials and direct
parent checks, acquire a Mach task port and matching audit token. Resolve only
`proc_signal_with_audittoken` from the system libproc library. Refuse unavailable
symbols without fallback. Change only the known child's audit-token generation
for a negative SIGTERM check; require ESRCH and an unreaped live child before the
valid-token SIGTERM. Export actual wait status, elapsed time, and post-reap token
rejection. Signal zero is invalid for this API. Do not force PID reuse or claim
that this bounded mismatch observation proves arbitrary process ownership.

There is no numeric-PID signal, UID-wide signal, detached descendant, service,
browser, simulator or arbitrary command. Denied operations wait for the child's
own deadline. Keep primitive outcome, child cleanup and binary/directory cleanup
distinct. Publish only fixed redacted observations, public source identity and
source hash. A malformed, missing or partial observation is a failed probe.

No result establishes an exclusive UID lease, creation-bound ownership, service
containment, stream/port closure, guardian loss/cancellation, private-artifact
custody or actual Chromium/CoreSimulator operation. Those require separate
reviewed implementation, adversarial verification and protected installation.
