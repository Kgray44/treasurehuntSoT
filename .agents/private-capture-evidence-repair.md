# Private capture evidence draft

This is a local protocol draft based on protected main
`b2d901af5646ce76b3b2bd5a88e1ad8563c2db57`. It does not authorize installation,
capture, upload, key retrieval, policy changes, finite reservation, qualification
dispatch, merge or consumer acceptance. Keep #776 and its source untouched.

Working encryption, decryption and provider-shaped fixtures belong exclusively
to `createPrivateCaptureFixtureRealm`. Generated keys and fixture access tokens
cannot mint production upload paths. Production publication, upload selection
and private-view entry points deliberately throw `POLICY_NOT_INSTALLED`; there
is no environment or JSON enable switch. The workflow policy gate precedes
finite reservation, and preparation gates precede planning or producer work.

The private branch keeps the established artifact, viewport PNG, raw WebM, trace
ZIP and paired-witness validators before encryption. It stops before canonical
promotion, preserves remapped review manifests plus untouched original producer
JSON, and encloses the plan, prepublication journal and invocation-owned runtime
and profile receipts. Historical canonical bytes remain unchanged. No plaintext
capture folder, staging, journal, plan, runtime, review or activation uploader is
available in the draft workflow. Existing separately classified encrypted raw
retention and allowlisted preparation progress retain their own semantics.

The fixture packet is purpose/version bound, has an encrypted private index and
opaque part names, and exposes only source/provider identities and ciphertext
metadata. Binding includes controller/base/candidate/tree, source/contract/plan,
provider run/attempt, workflow, session, policy digest and recipient fingerprint.
Publication tokens are live, realm-specific and consumed once; cloning,
concurrent selection, source mutation and partial sets must fail closed.

The [preparation companion](private-capture-preparation.md) continues checkpoint03
with explicit synthetic authenticated HTTP retrieval, archive digest/member/CRC/
ZIP64 checks, and private review/verify adapters. It preserves original source,
run, context, media, paired, attestation and custody checks and baseline reader
separation. Generated keys and callback credentials do not establish live
provider authentication. Real recipient fingerprints, authenticated principal
capabilities, live reviewer/verifier access, trusted upload-output wiring and
production installation remain unavailable. No private key may enter candidate
execution or public outputs. Native capture/build/cache admission always rejects
until actual write confinement and sufficient separately reserved capacity exist.

Do not promote these proposed transport ceilings to capture-capacity evidence:
trace256MiB, video512MiB, PNG16MiB, JSON/index8MiB, selected plaintext4GiB,
4096files, raw chunks8MiB, encrypted parts16MiB, encrypted aggregate9GiB,
provider archive9GiB+32MiB, public receipt64KiB. Private readback uses fixed-size
same-handle reads and opaque extraction names. Windows mode bits are not proof
of a private ACL. Effective provider expiry and authorized access must be checked
separately; requested retention remains90days. Public ciphertext is still
downloadable to repository readers.

Focused results and independent review are development evidence only. Preserve
all failed originals. Linux qualification, exact-source independent review and
protected landing remain separate later obligations. This incomplete capability
does not warrant a Feature Catalog fragment update.
