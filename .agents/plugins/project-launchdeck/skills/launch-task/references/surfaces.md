# Chat, Work, and Codex

Regular Chat is a first-class launcher. The package does not globally require a local executor. Use actual tools exposed in the invoking surface, regardless of namespace; Work examples do not restrict Chat tools.

| Operation                | Regular in-app Chat                                                                                                                                                    | Work / Codex                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Conversation context     | Gather accepted discussion decisions, unique requirements and accessible attachments using current context and exposed native reads.                                   | Read carried context and accessible referenced chats. Uploads are not automatically available in a worktree. |
| Repository context       | Use connected GitHub and accessible project sources to inspect current protected main, governance, Trim, dependencies and open work.                                   | Also use local search/files/Git, preserving unrelated work.                                                  |
| Contract and naming      | Prepare the compact contract and title in the existing Chat. Use the helper if executable, or actual native durable storage with equivalent locking/receipt semantics. | Run the helper against the single owner-local journal.                                                       |
| Separate task creation   | Use an actual native operation that creates and starts a separate Work chat in the existing Codex project with title, prompt and requested isolation.                  | Use verified native desktop project creation or actual runtime equivalent.                                   |
| Verification and cleanup | Read actual returned target IDs/status/context; prove destination, transferred requirements and Goal. Keep the source Chat intact.                                     | Verify target/project/title/Goal/progress; preserve existing chats and worktrees.                            |

Inspect available tool descriptions and schemas once per invocation. Map the roles above only to callable tools; do not invent names, endpoints, bindings, caller identity or durable storage. Do not print full catalogs or probe writes for discovery. ChatGPT-project-only creation cannot satisfy native Codex routing. GitHub and discussion tools remain useful when creation is missing.

The required experience is: discuss here -> Launchdeck gathers necessary context -> Launchdeck creates a separate implementation Work chat -> that target creates its Goal and starts execution. No manual copy/paste, source-Chat migration, "continue in Work" request, executor relay, browser or standalone API session is an acceptable substitute. A real platform permission gate cannot be bypassed or represented as automatic creation.

Regular Chat must load the installed workflow through its actual plugin/skill mechanism. Creator metadata inspection is not invocation. Previously reported Chat tests lacked native creation and executable skill exposure; a continuation handoff was attempted but does not satisfy this contract even if accepted. Direct Chat-origin creation remains unproved. Installation or a manifest flag cannot grant missing operations. Report the exact capability gap and prepared contract in the existing Chat if direct creation or safe retry state is unavailable.
