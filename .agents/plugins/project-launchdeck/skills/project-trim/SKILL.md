# Project Trim

This skill adapts the repository's accepted Project Trim v1.0-R1 rules. Read [repository bindings](references/repository-bindings.md) for source identities, drift handling, and accounting details; do not load the whole project record family. This plugin is a progressive-disclosure pilot, not new release authority or a new Project Trim phase.

Create a short task contract retaining initiative/increment/title, execution profile, context-packet requirement, unique scope, unique non-goals, special authorization only when needed, deliverables, and current completion authority. Retain the objective, exact phase, acceptance criteria, explicit gates, and launch/Goal marker. Keep exact identifiers when they affect correctness. Prefer a source path plus the decisive rule over copying an accessible document. If the target cannot access a source, carry the necessary excerpt rather than a useless link.

Remove greetings, motivational prose, repeated role assignments, generic quality/security advice already enforced by the host, chronological discussion, rejected approaches, and redundant summaries. Do not truncate to a fixed length or substitute vague “best practices” for concrete requirements. Never change “do not merge/tag/release” into permission to publish, or turn a conditional acceptance gate into optional work.

Select one of product-phase, bug-repair, documentation-only, infrastructure, security-sensitive, integration, or release-closure. Use STANDARD_AUTONOMOUS unless the human requests UNATTENDED_CONTINUATION. Build a minimum-sufficient context packet from current authority, ownership, source, schema/data, verification, dependency, and mainline delta. Reuse an accepted capsule and read/search ledger only when source bindings are still valid. Treat profiles as startup heuristics: unknown mappings, stale sources, conflicts, and required proof trigger targeted expansion. Context expansion never authorizes scope expansion. Never skip a required governing read to meet a budget.

Use only populated prompt sections. Avoid restating permanent repository guidance; tell the target to read current AGENTS.md and relevant authority. Keep a small source-bound packet pointer or ask the target to build one if available. When repository helpers are missing, construct a clearly labeled minimum-sufficient summary and expand conservatively; do not fabricate schema-valid packet evidence.

Budgets and size warnings are advisory only, with blocksProgress:false. Do not pass advisory Project Trim bands as Goal token_budget; only the human can request a hard Goal budget. Keep strong/default model settings unless explicitly authorized and validated otherwise. Numeric bytes/words are proxies, not billed tokens. Follow EXACT → RECONSTRUCTED → CALIBRATED_ESTIMATE → COARSE_ESTIMATE → UNAVAILABLE; absent defensible accounting use null, never zero. Never claim the 40–60% savings target was achieved without comparable live-task evidence. Persist only safe identifiers, digests, and aggregate counts—not raw prompts, transcripts, secrets, or logs.
