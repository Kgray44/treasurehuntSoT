# Security policy

## Reporting a vulnerability

Use GitHub's private vulnerability-reporting channel for this repository when it is available. If it is not available, contact the repository owner through their verified GitHub profile and request a private channel before sharing technical details.

Do not post exploit steps, credentials, private Chronicle material, access tokens, or personal data in public issues, discussions, pull requests, or screenshots.

## Scope and support

Reports about the current default branch and currently deployed project-owned services are in scope. Older branches, local modifications, and third-party provider outages may be outside support, but reports that could affect private material or account access should still be raised privately.

Include affected version or commit, a minimal reproduction, impact, and any mitigation already attempted. Please allow time for acknowledgement and coordinated remediation before disclosure; response timing depends on severity and available maintainers.

## Private Chronicle emergency

If material appears exposed, stop further sharing, preserve only the minimum evidence needed to report it, and use a private reporting channel. Do not copy the material into a ticket. See the [private-content runbook](docs/administrator/private-content.md) and [security architecture](docs/developer/security-architecture.md).
