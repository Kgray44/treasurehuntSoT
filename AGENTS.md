# Repository Instructions

1. Work from current protected main in an owned branch and worktree admitted through the [workspace lifecycle manager](.agents/workspace-lifecycle.md). Reuse a suitable owned workspace before creating another; register ownership and a finite peak allocation before hydration.
2. Read only the files and specifications relevant to the task; expand context only for a concrete uncertainty.
3. Use focused tests while developing. Do not use Sounding Line as a debugging loop.
4. When implementation is ready, open one pull request and let the ordinary Sounding Line final check verify it.
5. Merge after that check passes, then run a quick landed-tree smoke check. Finish through the lifecycle manager so verified merged checkouts, released processes, and disposable generated resources retire automatically. A specific recorded hold delays retirement only while its dependency exists; historical preservation instructions do not permanently retain redundant checkouts.
6. Use the exhaustive Sounding Line check only for releases or explicit full certification.
7. Do not create governance or maintenance work during ordinary product objectives.
8. Preserve unrelated work and never rewrite shared history.
9. Any task changing user-visible behavior follows [Product Experience Engineering](.agents/product-experience-workflow.md): design, run the actual experience, capture, independently critique, repair, and verify its human outcome before integration.
10. At startup run lifecycle recovery and reconciliation. Failed, cancelled and expired tasks release owned generated resources while preserving unfinished source and original evidence. Do not mark operational completion until retirement succeeds or the registry records its exact blocker.
11. Keep more than 30 GiB free separately on C: and D:. Before disk-consuming work, run the host ReserveGuard through Windows PowerShell with finite C:/D: write estimates; recheck every five minutes during long writers. The manager enforces a 75 GiB aggregate admission ceiling and a 12 GiB per-workspace peak, including dependencies, builds, browsers and temporary data. Existing external writers are outside this instruction's enforcement.
