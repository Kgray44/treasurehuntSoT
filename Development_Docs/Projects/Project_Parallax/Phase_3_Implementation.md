## Domain and runtime design

`adaptive-contracts.ts` defines strict versioned placement recipes: preferred/alternate/forbidden surface classes, surrounding context, relative offsets, height/orientation, clearance/free space, reachability, concealment, visibility, search region, confidence, accessibility and fallback. Invalid, ambiguous or unsupported inputs do not produce invented anchors. `adaptive-authoring.ts` provides guided defaults and an explicitly bounded phrase grammar; configured AI intent/critique remains a schema-validated advisory boundary.

`adaptive.ts` rejects unsafe candidates before preference scoring. Candidate enumeration is normalized; deterministic ties include the configured seed. It classifies high matches, acceptable substitutes, low-confidence fallbacks and no valid placement. Scene solving prioritizes the most constrained entity, prunes incompatible relationships and enforces non-overlap, separation, reveal/visibility, accessibility, render and interaction budgets. Limits are 16 entities, 32 relationships, 16 shortlisted candidates per entity, 4,096 search nodes and 512 diagnostic entries. Budget exhaustion and constraint conflicts return diagnosable fallback, rather than violating a hard constraint. Surface normals and authored rotations use full quaternion composition; player-facing placement requires viewer evidence.

The live Lens exposes a minimized resolution receipt: selected policy, seed, version/checksum, surface class, score/confidence band, accepted constraints and fallback. Candidate identifiers, physical poses and frame identifiers are omitted. Physical transforms remain transient adapter/runtime state. Existing immutable capsules without the optional adaptive extension retain their old checksums.

| Policy            | Logical scope and stability                                                                                                         |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| FIXED             | Existing authored placement remains unchanged.                                                                                      |
| PERSONAL          | Authorized actor plus lifecycle; accepted personal-placement behavior remains separate from shared scope.                           |
| ADAPTIVE_STICKY   | Version/checksum and lifecycle-bound seed; looking away, rerendering and ordinary tracking changes do not reroll placement.         |
| ADAPTIVE_PER_CREW | Version/checksum and canonical crew identity; durable logical decision survives reopening.                                          |
| ADAPTIVE_PER_RUN  | Version/checksum and canonical run; an authorized new run can change the seed.                                                      |
| ADAPTIVE_VARIANT  | Run plus authorized variant; replay retains its existing version/scope semantics.                                                   |
| CALIBRATED        | Reviewed version-bound semantic recipe retains adaptive safe resolution; calibration does not silently freeze physical coordinates. |

`service.ts` persists authorized logical identity/seed decisions, not physical room poses. Reopening the same scope reuses the identity. The runtime cache revalidates changed environment evidence against the complete recipe and relationships; invalid cached placement degrades safely instead of randomly selecting a replacement. A shared database identity does not establish physical cross-device alignment. Distributed shared anchors, relocalization and late-join alignment remain Phase 4.

## Optional field evidence and calibration

`field-contracts.ts` permits only bounded categorical metadata: surface, resolution/confidence, meaningful search duration, hint/reveal use, tracking recovery, fallback/capability limitation and placement-quality report. Consent disclosure explains purpose, Creator access, retention and withdrawal; declining has no progression effect. No room image, audio, coordinates, scan trajectory or EXIF is accepted. Automatic image transfer is disabled with zero transfer bytes: certified local person/face screening and the approved protected-media purpose are unavailable. Person-present, uncertain, no-consent and even apparently person-free candidates therefore all fail closed.

`field-service.ts` verifies active canonical membership, the exact published spatial version/checksum and resource ownership before accepting contribution or review. Idempotency prevents retry duplication; contributor/run/version uniqueness prevents repeated reports inflating maturity. Withdrawal deletes the retained observation and audits access. Retention is authored within 1–30 days; authenticated reads purge expired data, and the long-running Node runtime purges at startup and hourly. This is not deployment or a certified serverless scheduler receipt.

| Maturity         | Required software evidence                                                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEMANTIC         | No eligible physical report. Simulation remains separately classified.                                                                                                              |
| OBSERVED         | Eligible consented self-reported physical encounter for the pinned version. This is report provenance, not certified hardware attestation.                                          |
| CREATOR_REVIEWED | Authorized owner review with exact current draft/revision and eligible retained evidence.                                                                                           |
| CALIBRATED       | Sequential owner acknowledgement bound to the reviewed recipe digest, then an immutable definition release.                                                                         |
| VERIFIED         | Later independent eligible reports from distinct actors and runs for the calibrated released version. This label records the software evidence rule, not physical AR certification. |

Concurrent first reviews are serialized by a unique sequence, and review compare-and-swap rejects stale revision/evidence. Changing the recipe invalidates the review/maturity acknowledgement and starts a new review cycle. No simulation promotes physical maturity. Existing spatial releases and Chronicle references remain immutable. Quality summaries separate simulation from physical self-reports, show distributions and mean/median search times, and give bounded actionable guidance over at most 200 authorized records.

## Discovery and canonical play

Every required adaptive objective has expected/maximum search duration, bounded hint stages, exact reveal, direct accessible mode, tracking/low-confidence recovery and authored alternative completion. Only the current mandatory objective is searched; sequential/visible budgets prevent hidden spoilers from appearing together. Meaningful search counts foreground, unlocked, permitted, tracked, open-Lens activity inside the search region. Background, interrupted tracking/permission, story reading and irrelevant regions pause it. Monotonic elapsed time is bounded, stored per actor/instance/version/entity in session state and excluded from local replay writes. Broad viewed-sector/near-miss hints remain transient.

Low confidence with prolonged search is treated as possible resolution failure. Show me/Guided View exposes the clue and accessible interaction; normal passage controls remain authoritative for completion. Native adapters currently lack semantic environment-candidate evidence, so they degrade honestly to Guided rather than fabricating surface understanding. Existing interaction observations remain authorized, version-bound and idempotent; Parallax does not write a second progression engine.
