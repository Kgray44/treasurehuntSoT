# Direct Spatial Community publishing

SC-07A connects saved Creator-owned Spatial Studio content to Harborlight listings, immutable releases, package scans, moderation and Library installation. The implementation is an owned candidate. Protected integration, independent product experience acceptance and owner acceptance remain separate decisions.

## Creator journey

Spatial Studio exposes one **Publish to Community** workflow from a saved personal item, SC-00C Library details and context actions, Scene Manager and an owned Environment. A saved composition extracted from the Creator's current owned source can use the same workflow; the server reconstructs its dependency-closed content from that source before granting redistribution eligibility. A source with a known redistribution or privacy limit instead shows **Review publishing limits** and the same workflow explains it before authoritative server review; it is not presented as ready to publish. The guided dialog identifies the exact saved revision and previews its owned objects or Environment fixtures. This first preview remains private; the later server-verified review defines the Community package. The Creator enters title, description, tags, license, credits and rights acknowledgment, inspects resolved content, then sees the sanitized package before an explicit submit. Its final review puts the immutable-release and moderation consequence above the package preview and requires a separate acknowledgment of the included content, credits, warnings and outcome. Keyboard focus wraps inside the modal. A prior listing for the same source can be selected to submit a new immutable release. Saving a draft or creating a Parallax version does not publish it.

A successful submit creates a Harborlight listing and release in `READY_FOR_REVIEW` or `UPDATE_PENDING`. The result says that moderation is next. If the response is lost, the dialog says that the outcome is unconfirmed, preserves the saved source, and asks the Creator to review the same package before retrying; the exact retry returns the recorded release without creating another. A changed update waits for the pending review to finish. An Admiralty operator with Community moderation capability can open the pending listing, open and inspect its exact sanitized JSON package, checksum, rights declaration, license, credits and Environment privacy warning before acknowledging review, and approve it with recent privileged assurance. The route denies self-moderation, requires the reviewed release ID and checksum, and transactionally records publication with the outbox and administrative audit. The listing link is usable after that separate decision. The Community detail page then offers an exact-release installation review. Installation creates a pinned read-only Spatial Library item and, for a Scene, a pinned local Environment dependency. An installed composition retains its Compositions Library identity, is labeled **Community installs**, and can be added to a fixed Scene. Its Library details do not offer working-item rename or archive actions. An installed Environment is also labeled **Community installs**; both its Library details and card menu say **View Environment**, and the Scene Manager disables editing. An editable derivative requires a deliberate separate copy; installed content cannot be republished as Creator-owned source without verified redistribution lineage.

## Package and privacy boundary

The server reads an owner-scoped exact saved revision, validates its stored checksum and resolves its pinned Environment. A new schema-validated public projection selects approved spatial and Environment fields explicitly, then parses the projected documents. New top-level authoring fields therefore require a deliberate projection change before they can enter a Community package. The package excludes private draft scope, Chronicle ID, working-copy flags, source photo labels, Vision references, calibration receipts and private account data. It refuses reconstructed room geometry and measured room evidence. Manual synthetic Environments still require an explicit geometry privacy acknowledgment because geometry can be sensitive even without photos. The creator inspects the exact package before submission.

Referenced binary models, textures and audio are blocked because this source path does not resolve their bytes, scanner receipts and redistribution rights. SC-02 physical-model references are also blocked: their original asset package requires owner authorization, and the current JSON projection cannot establish that right or package dependency. Unverified remix lineage, stale or edited extracted compositions, missing dependencies, built-in Environments and installed read-only sources also fail closed. Adding a saved composition to another Scene records reuse lineage, so a composite Scene cannot bypass that refusal. The ordinary supported package therefore contains JSON authoring content only. The composition marker is explicit in its sanitized package and restored on installation; a marker alone does not establish ownership. Parametric effects represented by eligible saved Parallax drafts follow the same asset path; collections and physical-model composites require further canonical package support. Only the Community visibility with a working public listing route is offered. These limits are surfaced in the workflow and must not be described as accepted publication of unsupported content.

The package uses Harborlight's manifest, checksums and scanner contract. License policies live in the existing `CommunityLicensePolicy` authority. The additive SQLite and MySQL migrations seed three built-in redistribution choices without replacing existing rows. The transaction records the release, package, package items, ownership declaration, outbox event and audit event together. Installation verifies the current approved release and package checksum and writes Exchange operation, mappings and Library records together. Editing a Studio source after submission does not rewrite the release payload.

## Validation boundary

Focused package and isolated SQLite integration tests cover private save without publication, preflight, license and dependency rejection, private source-label exclusion, immutable release payloads, Scene and owned Environment packaging, verified current-source composition lineage, refusal after parent revision changes, pending moderation, approved exact-release installation, verified-installation review eligibility, stable installation retries and update releases. The browser journeys use a production build, owned loopback server and synthetic accounts. Six journeys passed direct Studio publishing, a saved-source preview on desktop and mobile, all five mobile wizard stages, package JSON keyboard scrolling, forward and reverse Tab containment, Escape focus restoration, Community listing, mobile exact-release installation, verified review and read-only Studio return. The installed Studio status identifies the release rather than calling it a working draft. A known unlicensed physical model displayed **Review publishing limits** instead of **Publish to Community**; server review then refused it on mobile, created no listing and preserved the saved source after reload. A saved Scene journey previewed its pinned Environment revision, then reviewed and submitted the Environment as a separate package item; the private photo source label was absent. A direct owned synthetic Environment journey began in Library details, previewed its fixture, reviewed a sanitized package without its private source label and a visible geometry warning, submitted to moderation and installed into a second Creator's read-only Environments Library. Both installed Library action entries say **View Environment**. A saved composition journey began in Library Compositions, inspected the marked package, opened a public listing labeled **Spatial composition**, and installed into a second account's Compositions tab. The interrupted-response journey dropped the response after Harborlight recorded a release, observed an unconfirmed outcome in the dialog, then re-reviewed and recovered that same release by exact retry. The refusal is focused and scrolled into view. A synthetic moderator account and privileged-assurance fixture exercise the actual Admiralty review screen and approval route for asset, Environment and composition releases; the browser suite checks that a Creator cannot read the moderator review and that approval stays disabled until the moderator opens the exact package and acknowledges it. Domain tests reject self-moderation and stale checksums, and approve a pending update while preserving an installed older release. These tests establish the application path, not a human moderation decision. An earlier C: isolated SQLite run stopped at synthetic account creation because of a disk-full error; the final passing suite used fresh task-owned SQLite on D:.
