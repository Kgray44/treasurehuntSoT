## Storage, integrity and compatibility

No schema migration is introduced. PARALLAX_STUDIO is separated from the generic reusable-library UI. Working drafts use the existing mutable revision counter and reserved version number zero; a release inserts a new immutable positive version and atomically claims the revision. Historical releases never update when a draft changes. Every load and attachment verifies canonical checksums and owner/definition/version bindings. Chronicle-only items cannot attach to another Chronicle until explicit My Library promotion. Published capsules embed immutable content, so a runtime does not dereference a mutable library item.

The optional `studio` extension adds no default fields to P1 releases. Existing P1 checksums and capsules round trip unchanged. Native scene transport, capability discovery, companion compatibility and Device Lab ownership are retained. Behaviors emit visual/nonauthoritative interaction state, never Chronicle progression. UI accessibility and Guided meaning remain available without native AR.

## Explicit limits and remaining gates

The native renderer continues to support the accepted P1 plane/text kinds. Import manifests validate portable type, checksum, units, scale, complexity and provenance, but arbitrary model/texture/audio rendering is unavailable and blocks release. Complexity and synthetic fit estimates are not measured device frame rates. Crew preview is a second synthetic viewpoint, not Crossdeck synchronization. Remote comparison is fixed-scene comparison, not P3 adaptive resolution or calibration. Vision references preserve typed contracts without claiming Watchglass recognition.

AI authoring requires owner-configured `PARALLAX_AUTHORING_AI_URL` and `PARALLAX_AUTHORING_AI_TOKEN`. No live provider is available in this task; schema/materialization/unavailable behavior is software-tested, while live model quality and provider operations remain an environment qualification gate. The provider must return the strict requested JSON shape. Tokens remain server-side and model output cannot mutate content without Creator review.

Representative-device owner walkthrough, D4 physical AR evidence and any D5 field claims remain separate. Synthetic D0/D1 tests cannot certify room suitability, placement accuracy, real tracking, multi-device truth or owner product acceptance. Push/PR, protected-main integration, landed-tree smoke, deployment and release remain unauthorized here.
