## Human objective and ownership

A person uses one canonical account to read or author the same published
Chronicle, open a spatial clue, inspect its authorized content and return to
their existing workspace. Shared Scene validation must preserve the other
surfaces that consume the canonical publication, private archive or session.
Public projections must continue to exclude the private fixture.

NCL-01 coordinates the affected consumer regression experience. Homeport keeps
screen/navigation authority; Wayfarer keeps account and private history;
Harborlight keeps public projections; One Voyage keeps editions, memberships
and progression; Drydock and Shipwright keep validation and authoring;
Admiralty keeps privileged observation and consent; Spatial Pilot keeps its
existing private development gate. No new session, publication, history,
progression, native transport or experience engine is introduced.

partition the 135 previously uncovered paths into exact files. They do not use

## Composition and state design

Preserve the existing product composition rather than refitting these domain
screens as part of NCL. Personal Harbor remains a private account task; Passport
remains a separate record-led archive; Community remains public content and
search; the Chronicle Library remains the publication catalog; Studio remains
authoring; Captain remains live Voyage authority; and Admiralty remains scoped
observation. A capability label is never substituted for the promised task.

Each family keeps its existing heading and primary work area, readable state
explanation, labeled controls and immediate contextual return. A private title
must not appear in public results. An empty Community district is truthful even
when the separate public Chronicle Library contains a generic published story.
Creating a fake CommunityListing would erase that distinction.

The executable state obligations include registration readiness and safe
sign-in return; actual account/Profile readiness; Passport and populated
private history; public empty search and recovered results; actual Studio
editor readiness; Captain's empty Voyage task and eligible edition list;
Admiralty's non-enumerating empty search; and unprovisioned private trials with
an empty Player library. The adverse public search uses the real private title,
not a mocked response. Required focused tests additionally check private detail
authorization, non-owner trial denial, unchanged draft validation and missing
private content in public catalog results. Native pending, rejected and
accepted Inspect remain covered by their actual canonical handoff tests;
ordinary browser capture does not pretend to exercise an unavailable native
camera.

The new Admiralty journey starts at Personal Harbor, verifies the actual
synthetic Administrator heading, and uses the visible account menu to enter
Admiralty. It retains Platform Overview, the real People known-clue empty state
and Return to account, then verifies the same exact account heading. The private
trial journey retains its directly authorized development URL; no visible Sea
Trials entry from Personal Harbor is invented. Its existing Player Library and
Home path continues through the real account menu to Personal Harbor, where the
exact synthetic Owner heading is visible again.

Admiralty's tokenized shell and the private trial's development shell do not
render the ordinary account button. For these two new experiences only, the
unconditional Voyagewright Home link supplies navigation-only continuity of its
`href`. It does not prove account identity. Real UI sign-in, the canonical
role/owner gates and exact account headings at setup and contextual return retain
that separate obligation. Other family selectors, protected journeys, feedback
bounds and privacy assertions remain unchanged. This corrects the prepared new
design before capture and removes no governed obligation or production control.

Every new role journey runs on desktop and constrained mobile, in normal and
reduced motion. Actual keyboard activation, focus, overflow, serious/critical
accessibility findings, feedback and contextual return remain blocking.
Useful consumer feedback keeps the existing five-second published-consumer
envelope. This creates a browser feedback obligation and extends no native,
instrumentation, renderer or hosted-job deadline.

Eight new family experiences contribute 32 role/device/motion contexts. The
registration addition contributes two more. All selected protected journeys,
states, roles, debt and existing paired requirements remain additional; the
exact frozen plan supplies the authoritative full denominator.

SQLite and the production application. Dedicated ACTIVE/VERIFIED synthetic
Player, Captain, Creator and Administrator identities use canonical persisted

that this real sign-in established. Each context still verifies the actual
account identity and starts fresh UI state. No contract injects a token,
cookies, global role bypass or a replacement authentication policy. Existing
sign-in limits remain in force.

not promoted to validated; its checksummed edition and completed Player
Voyage/membership/events remain canonical. The actual history service creates
its projection. No history row, Drydock result, native session/surface, consent,
keepsake or physical acceptance record is fabricated. Public browse fixtures
remain separate from this private Chronicle.

The actual consumer journeys and adverse checks live in
[the focused browser specification](../../../tests/e2e/ncl01-consumer-continuity.spec.ts).
Their declared cases are not executed counts. The newly prepared design
requires a frozen, accepted plan followed by current actual-app capture,
independent media review, bounded repair and ordinary protected verification.
Neither the earlier source-bound D1 success nor preserved native graphics/UI
receipts can replace those new consumer captures.
