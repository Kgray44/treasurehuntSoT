# Hold the Bearing operations record

This is the development candidate's engineering runbook. Protected integration,
production deployment, signed native release qualification and physical field
acceptance remain pending. It describes source controls, not an operated production
service. The [design record](Project_Landfall_Phase_4_Native_Companion_Design.md)
and [Device Lab authority](Project_Landfall_Phase_4_Device_Lab_Addendum.md) govern
scope and evidence. One Voyage remains the only progression writer. Provider
restoration, a geofence wake or a notification must never confirm an arrival.

Notification return separates account authentication from Voyage authorization.
An absent or expired account requires sign-in. An authenticated account whose
membership was removed or whose pinned session is unavailable returns to Player
home without exposing that Voyage. The server rechecks current authority on each
tap; a persisted native cookie or opaque claim cannot restore removed access.

## Detection and retained evidence

The authorized Admiralty provider view exposes configured capabilities, bounded
recent demand health, credential availability and recovery state. It does not probe
providers when viewed. A successful HTTP response alone is not provider health.
Process-local remote health expires after five minutes and resets with the process;
it is neither fleet history nor a service-level objective. Unconfigured or unknown
quota/credential expiry remains unknown.

Server operational events retain finite operation/outcome/duration categories.
They exclude account and session identifiers, precise coordinates, queries, keys,
pairing codes, raw sensor reports and provider exception text. Record incident time,
deployed commit, native version/platform, finite capability/outcome and recovery
result. Reproduce with public synthetic fixtures in an owned isolation database.
Retain artifact hashes, source/tree identity, evidence class and cleanup results.
Do not put real private content in a Device Lab receipt or screenshot. Native lab
diagnostics are debug-only bounded counters or categories, not production telemetry.

## Existing independent controls

| Capability                                     | Source control and safe fallback                                                                                                                                                                                           | Limits                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Configured geocoding, routing or elevation     | Remove that service's entry from the valid server-only `LANDFALL_REMOTE_DATA_CONFIG` and roll the deployment through its existing release process. Keep other entries valid. Released authored guidance remains available. | Configuration accepts one entry per supported kind, at most three. Invalid configuration or a missing required bearer credential fails the entire remote configuration closed; validate the edited configuration before deployment. No client-selected endpoint or global live switch.                                                                                                                                     |
| All configured remote suggestions              | Omit `LANDFALL_REMOTE_DATA_MODE=ephemeral-instance` when rolling the deployment.                                                                                                                                           | Broad fallback; use the individual valid-entry change for a single provider outage.                                                                                                                                                                                                                                                                                                                                        |
| New signed offline regions                     | Remove server-only `LANDFALL_PACKAGE_SIGNING_KEY` or `LANDFALL_PACKAGE_KEY_ID` through the deployment's secret/configuration process. Preparation reports signing unavailable.                                             | The same signing configuration derives notification return-handle encryption: removing or rotating it also affects minting or resolving those handles. This is not an independent region-only kill switch. It does not revoke already-authorized cached content; its bounded lease still applies. Local removal and access clearing have separate effects. No private signing key belongs in an artifact or client bundle. |
| Native background wake                         | The Player can clear the prepared region and revoke the OS background-location permission. Source replacement confirms old OS region removal before adding another.                                                        | No fleet remote kill control is implemented. OS timing and physical-device behavior need their own acceptance.                                                                                                                                                                                                                                                                                                             |
| Native notifications                           | Use the separate notification permission and the Player's consent setting; clear the prepared wake region.                                                                                                                 | Turning off a notification does not remove foreground authored guidance. A tap still requires current server authorization.                                                                                                                                                                                                                                                                                                |
| BLE, UWB/Nearby Interaction, NFC and camera QR | Use each deliberate operation's stop/cancel control or revoke that OS capability. Backgrounding and power pressure stop bounded optional acquisition.                                                                      | These are independent device/session controls, not deployment-wide remotely operated feature flags. Unsupported hardware remains readable fallback.                                                                                                                                                                                                                                                                        |
| Sensor hints                                   | Stop optional sensor acquisition; constrained power or background lifecycle stops it. Retain location/context confidence gates and readable guidance.                                                                      | Sensor hints alone never establish physical arrival. No server-operated native sensor kill switch exists.                                                                                                                                                                                                                                                                                                                  |
| Watchglass                                     | Recognition remains `NOT_CONFIGURED`; no recognition engine is introduced.                                                                                                                                                 | Do not route around this state with another evidence or progression writer.                                                                                                                                                                                                                                                                                                                                                |

The repository has no general fleet native feature-control service in this
candidate. Do not describe example flag names from the governing document as
implemented switches. A native regression can be contained on an affected device
through these controls and through the deployment owner's native release rollback.

## Incident handling

| Incident / detection                                                                                   | Impact and safe degradation                                                                                                                 | Containment and recovery                                                                                                                                                                                                                                                          | Evidence and required user communication                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Map data outage: renderer/resource failure or unavailable background                                   | Authored released routes, objectives and readable list remain available. External tile availability does not establish position confidence. | Disable the affected configured map choice through its existing deployment/authoring configuration; do not substitute an unapproved endpoint. Restore licensed configuration, then test actual released display and offline fallback.                                             | Record finite renderer/resource outcome and synthetic screenshots. Tell affected Players that the background is unavailable and guidance remains readable; make no safety/accessibility certification.                |
| Geocoding outage: configured geocoder unavailable, rate limited or timed out                           | Search suggestions stop; existing authored places remain intact.                                                                            | Remove only its valid configuration entry when needed. Respect retry state; restore the credential/endpoint agreement and verify one deliberately consented request.                                                                                                              | Record service kind, finite outcome and retry recovery. Explain unavailable suggestions and continued authored place selection.                                                                                       |
| Routing outage: configured router failure or mode mismatch                                             | Online route suggestions stop; Creator-authored routes remain guidance.                                                                     | Disable the router entry, retain authored route data, restore the configured mode/profile, then verify demand and fallback. Never rewrite authored progression from a provider response.                                                                                          | Record route service/mode category without origin/destination coordinates. Explain that online suggestions are unavailable and authored routes are not certified safe or accessible.                                  |
| Location provider failure: denied/revoked permission, stale fix, unavailable provider or poor accuracy | Confidence degrades and automatic physical evidence cannot qualify.                                                                         | Stop acquisition, show the current permission/provider state and preserve readable/manual guidance permitted by the objective. Reacquire deliberately; require fresh qualified evidence after recovery.                                                                           | Record finite permission/freshness/confidence state. Explain the concrete unavailable or approximate state without implying arrival.                                                                                  |
| Notification failure: permission denied, no notice or failed return                                    | A wake hint may not be shown. Foreground Journal remains usable.                                                                            | Keep permission requests contextual. Clear/reprepare the bounded region if authorized; validate an actual OS notice/tap and fresh server return separately. Do not manufacture a tap or progression event.                                                                        | Record notice/return authorization categories; never retain the opaque return handle. Explain how to reopen the Journal and which permission is missing.                                                              |
| Background geofence malfunction: registration/clear failure or absent wake                             | Automatic wake is unavailable; no arrival is accepted from a boundary event.                                                                | Clear the region and verify removal. Reprepare only after current consent, precise/background permissions and fresh authorization. Refuse replacement when old OS removal fails.                                                                                                  | Retain registration/clear category and actual OS delivery classification. State that nearby alerts may be unavailable; require foreground confirmation under the existing objective policy.                           |
| Offline package corruption: signature, resource hash, encryption or scope failure                      | The affected region is corrupt/unavailable. Another readable saved projection does not make that package ready.                             | Remove the affected device region, reauthorize while online and download verified resources again. Never bypass integrity, lease or membership checks.                                                                                                                            | Record corruption class, source and synthetic resource hashes without package contents. Explain that the region must be refreshed and Chronicle history is preserved by local region removal.                         |
| Cache/storage exhaustion: quota or private-store write failure                                         | Download remains partial/failed; restart preparation may be unavailable.                                                                    | Pause acquisition, remove an unneeded region through its UI and retry a bounded region when capacity recovers. Preserve current history and do not delete unrelated browser/app storage as a diagnostic shortcut.                                                                 | Record finite capacity/write outcome and measured fixture bytes. Explain space requirements and whether access is tab-only or has a bounded native restart lease.                                                     |
| Privacy incident involving coordinates or private tokens                                               | Potential disclosure requires deployment-owner incident handling.                                                                           | Stop the affected sharing/acquisition path; revoke compromised credentials if relevant; preserve restricted evidence through the owner's incident process. Inspect finite logs and use synthetic reproduction. Do not copy suspect real content into repository records.          | Record commit, operation category, exposure class and remediation status. The incident owner must determine and deliver accurate affected-user communication; this candidate supplies no legal notification workflow. |
| Provider credential rotation: unavailable/expired credential or suspected disclosure                   | Its optional service becomes unavailable.                                                                                                   | Rotate through the existing secret store, update only the server-side environment reference, validate configuration and roll the deployment. Remove the service entry while recovering if other services must remain available.                                                   | Retain credential-availability category and post-rotation synthetic demand result. Communicate service interruption; never display, log or archive credential values.                                                 |
| Rate-limit exhaustion: finite retry/rate-limited state                                                 | Optional remote suggestions or preparation pauses.                                                                                          | Respect bounded retry; reduce demand, disable the affected entry if needed and verify recovery without a probe loop. Preserve authored guidance.                                                                                                                                  | Record demand/outcome/retry categories. Explain the temporary limit and available fallback, with no invented quota remaining or recovery promise.                                                                     |
| Corrupted native release: install, bridge, package or launch regression                                | Native acquisition/restart may fail while the first-party web Journal remains available.                                                    | Pause native distribution through its existing release owner, restore a previously qualified signed release and test origin restriction, bridge, permissions, private storage and canonical reconciliation. Do not install an unsigned diagnostic build as a production recovery. | Bind version, signing/package hash and source to actual device checks. Explain affected capability and web fallback. Candidate unsigned build/manifest analysis alone is not release qualification.                   |
| Sensor-provider regression: malformed/inconsistent motion, heading, barometer or orientation hints     | Context confidence loses optional assistance. Position and arrival gates stay independent.                                                  | Stop the optional provider, keep uncertainty explicit, restore its qualified implementation and rerun malformed/lifecycle/power tests plus actual device acquisition. Do not compensate by fabricating distance, floor or heading.                                                | Retain finite provider/confidence outcomes; raw continuous traces remain private. Explain unavailable optional assistance and readable fallback.                                                                      |

Recovery requires the failed capability's actual verification, source identity and
cleanup evidence. Preserve failed receipts. A provider simulation cannot close a
native OS failure; a native emulator result cannot close a real-device or field
gate. Protected qualification and production-release approval remain separate
from executing this runbook.
