# Project Homeport Phase 5 test plan

## Purpose and authority

This plan binds the frozen route-reachability architecture to isolated,
source-driven evidence. It is Project Homeport Phase 5, not Project True North.
It is a plan, not a result. Sounding Line finalizer decisions are authoritative;
direct Node, Vitest, Playwright, schema, documentation, and build commands are
diagnostic until admitted into an exact-source Sounding Line receipt.

- Server: task-owned process on a verified-free port with reuse disabled.

## Contract and unit families

### Census and registries

- Discover page and route sources, route groups, dynamic/catch-all segments,
  layouts, not-found, and error boundaries without a hard-coded total.
- Reject omitted/phantom/duplicate sources and inventory/screen/shell/node drift.
- Enforce unique IDs, exclusive classifications/shell modes, valid parents,
  canonical targets, capabilities, source collections, and edge references.
- Require parameter metadata for every dynamic route and an exact disposition
  for tokenized, compatibility, development, internal, and deprecated routes.

### Graph and authorization

- Traverse anonymous, Player, Captain, Creator, full-capability, Moderator, and
  restricted graphs independently.
- Require every ordinary route to be eligible-root reachable and every dynamic
  route to have a visible source surface.
- Prove protected edges cannot be traversed as authorized by an ineligible
  profile.
- Reject missing targets, redirect/parent cycles, self-loops, direct-URL-only
  ordinary routes, placeholder targets, missing exits, and stale evidence.

### Dynamic, tokenized, compatibility, and parity

- Bind each dynamic parameter to an allowlisted visible source and test empty,
  invalid, private/foreign, removed, archived, and quarantined behavior where
  applicable.
- Exercise valid, malformed, expired, consumed, and revoked token states without
  storing token material and prove ordinary-navigation exclusion.
- Exercise every compatibility/redirect source after its canonical natural path
  is proven; verify termination, safe return/query handling, active state, no
  privilege broadening, and no competing UI.
- Compare desktop/mobile node and edge membership, accessible names, keyboard,
  touch, parent/return, and explicit exception rationale.
- Run the updater twice and require byte-identical artifacts with historical
  Phase 0 through Phase 4 records preserved.

## Component and server coverage

Component tests cover global/workspace/account navigation, Community district
navigation, Personal Harbor sections, breadcrumbs, parent returns, empty/error/
permission recovery, compact/immersive exits, compatibility/tokenized panels,
accessible labels, active state, keyboard/touch, Escape/focus behavior, mobile
rendering, href validity, and stable fallbacks.

Server tests cover public/private dynamic projections, owner-only source lists,
pagination continuity, removed-item behavior, canonical URL generation, safe
return generation, token/compatibility redirects, and route authorization.
No projection may be widened to make a route appear reachable.

## Evidence and freshness

Required representative evidence IDs are `HP-P5-EV-A` through
`HP-P5-EV-AD` as defined by the governing Phase 5 brief. Each image and route
receipt is checksum-bound to the exact implementation source. Visual review
rejects missing parent/return, dead-end states, desktop-only or pointer-only
entry, label drift, obsolete compatibility UI, generic permission sign-in,
broken href/error overlay, compiler artifacts, unsettled routes, or typed-URL
ordinary proof.

## Required test contracts

Phase 5 registers the governing `homeport.route.*` contract family for source
parity, classification, graph reachability, ordinary entries, dynamic sources,
invalid/private denial, token/compatibility safety, redirect integrity,
parents/dead ends/recovery, desktop/mobile and keyboard/touch parity,
compact/immersive exits, natural-before-direct proof, deprecation/development
disposition, labels, idempotency, drift, route receipts, source binding, and
Phase 1 through Phase 4 regression.

Every authoritative case records a stable ID, contract, owner, tier, risk,
source paths, fixture, database/browser/port ownership, hard budget, retry
policy, and release relevance. No unregistered test is authoritative.

## Acceptance sequence

1. Run the source census and architecture/schema checks.
2. Run focused registry, graph, component, server, and updater tests.
3. Run the Phase 5 browser family against a committed implementation source.
4. Retain route receipts, screenshots, traces, reports, and rejected evidence.
5. Run Phase 1, Phase 2, Phase 3, and Phase 4 regressions.
6. Run formatting, lint, types, docs, Feature Catalog, privacy, schema, and build
   gates in the isolated runtime.
7. Run Sounding Line impact planning without manually narrowing the graph.
8. Require exact-source Sounding Line subsystem and mainline `RELEASE_GO`.
9. Verify canonical database hash, branch/remote equality, 0/0 divergence,
   released ports/processes/leases, and task-owned runtime cleanup.

Phase 5 closure may close HP-NC-014 only when the source-driven graph reports no
unexplained ordinary orphan. Phase 6/7 findings, merge, deployment, live-user
proof, owner acceptance, and product acceptance remain outside this plan.
