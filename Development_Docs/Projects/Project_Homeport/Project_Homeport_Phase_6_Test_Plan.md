# Project Homeport Phase 6 test plan

## Purpose and authority

This plan binds the frozen product-surface architecture to isolated, source-bound evidence. It is Project Homeport
Phase 6, not Project Lanternwake. Sounding Line is the only release-decision authority; focused Node, Vitest,
Playwright, schema, documentation, privacy, and build commands remain diagnostic until admitted to a finalized
receipt.

## Owned resources

- Retained worktree and branch only: `C:\Users\kkids\Documents\Codex_TreasureHunt-homeport` on
  `codex/project-homeport-product-reality-recovery`.
- Task-owned copy of the canonical SQLite database, browser profile, media/storage roots, report roots, and port.
- Reserved synthetic accounts, Chronicles, sessions, records, tokens, moderation cases, and media references only.
- Canonical `prisma/dev.db` remains read-only and is hash-checked before and after validation.
- Committed evidence is limited to public-safe screenshots and checksum/source/fixture metadata.

## Contract families

The Phase 6 authority discovers every current app page and proves unique screen identity, source parity, criticality,
visual maturity, component-family consumers, state applicability, recovery, responsive coverage, accessibility,
motion ownership, media fallback, mutation feedback, and artifact idempotency. The 55 new `homeport.surface.*`,
`homeport.state.*`, `homeport.responsive.*`, `homeport.accessibility.*`, `homeport.motion.*`, `homeport.media.*`, and
`homeport.mutation.*` contracts are registered with `unit.homeport`, `component.homeport`, and `browser.homeport`.

## Focused and component evidence

- Node authority: `tests/homeport/phase6-surfaces.test.mjs`.
- Dialog focus trap, Escape, inert background, and focus restoration: `ActionDialog.test.tsx`.
- Image failure and named fallback: `ResilientImage.test.tsx`.
- Auth, restriction, unavailable, and session decisions: `AccessDecisionState.test.tsx` and
  `AccountFlow.homeport.test.tsx`.
- Player/Captain libraries, waiting room, Studio workbench, and mutation feedback: the corresponding component tests.
- Generator runs twice and requires byte-identical output while preserving historical Homeport source identity.

## Browser matrix

The production-runtime Playwright lane covers 12 critical screens at standard desktop, modern mobile, compact
desktop, tablet landscape, tablet portrait, narrow mobile, and an effective-200-percent layout viewport. Seventeen
additional high-risk/context screens receive desktop/mobile evidence. Alternate captures cover a pending dialog,
permission restriction, invalid/expired/consumed/revoked token states, no results, and reduced motion.

Each capture records screen, source SHA, fixture version/checksum, viewport, state, motion mode, accessibility result,
overflow result, file path, and SHA-256. Automated accessibility requires zero serious or critical axe findings where
run. Every capture is then inspected by Codex; this review is not owner acceptance or physical assistive-technology
proof.

## Closure gates

Closure requires the Phase 6 and aggregate Homeport validators, documentation and Feature Catalog gates,
terminology, formatting, TypeScript, ESLint, privacy, both Prisma schema validations, SQLite client restoration,
production build, staged-diff privacy scan, and finalized Sounding Line subsystem and mainline `RELEASE_GO`. No schema
change means no migration is authorized. Phase 7, owner walkthrough, deployment, and acceptance remain excluded.
