## R22 actual-byte pre-source admission

The [R22 recovery disposition](../../Programs/Sounding_Line/evidence/crossdeck-pre-source-byte-gate-20261020-r22/causal-disposition.md)
preserves successful R21 capture and its spent, malformed review11. The existing
owner/custodian must use the controlled source gate for the replacement review12.
A parsed JSON/count/citation summary cannot release source. No later canonical
judgments or fabricated ACCEPTED rows are needed to run the first-pass check.

Keep the fresh critic's initial context free of source, contracts, history,
producer review packets and builder rationale. Provide only neutral identities,
rubric and current media. After actual viewing, freeze the original UTF-8 JSON
using the canonical first-pass fields below. Do not replace evidenceIds with
mediaIds, or caseId/contexts with scenario/devices. Missing evidence fails the
check; do not invent citations or observations to fill required fields.

The custodian prepares a private source-pointer/text packet, keeping it away
from the critic, then runs the installed accepted-base gate:

```sh
node <accepted-authority>/scripts/sounding-line/experience-review-source-gate.mjs --workspace <owned-candidate-checkout> --base <accepted-main> --candidate <exact-captured-candidate> --identity <actual-critic-metadata.json> --observations <frozen-original.json> --bytes <original-byte-count> --sha256 <original-byte-sha256> --capture <current-protected-capture-artifact-id> --packet <custodian-only-source-packet.txt> --output <new-private-output-directory>
```

The identity file supplies the fixed R22 protocol kind and actual reviewer,
task path, builder and criticCreation metadata. The command reads the actual
frozen file, authenticates the current capture/original prepare, and applies the
same first-pass predicates used by final review. It fsyncs create-only
first-pass.original.json and pre-source-admission.original.json before reading
the input source packet. Only source-packet.released.original.txt from a
successful new output directory may be handed to the critic. Preserve every
failure; a failed check grants no repair/refund/retry entitlement.

The command returns PASS_STAGED_NOT_DISCLOSED, with a separate
source-packet-stage.original.json. It does not send a message or claim source
was disclosed. The existing authorized custodian delivers the exact released
packet through the native reviewer route and verifies the real native message
and earliest exposure time. An ambiguous/failed send is not DELIVERED.

The final mediaFirstReview envelope includes the exact preSourceAdmission and
sourcePacketStage objects from the retained originals, plus sourceDisclosure:

```json
{
  "kind": "CROSSDECK_NATIVE_SOURCE_DISCLOSURE_1",
  "status": "DELIVERED",
  "preSourceAdmissionDigest": "<shared semantic digest of exact PASS object>",
  "sourcePacketStageDigest": "<shared semantic digest of exact STAGED object>",
  "reviewerContext": "<actual same fresh critic>",
  "verifiedByContext": "01a14744-5390-77a1-8532-5c32db6980eb",
  "nativeMessageId": "<actual verified native disclosure message ID>",
  "sourcePacketSha256": "<exact staged packet hash>",
  "startedAtUtc": "<earliest actual source exposure; matches sourceInspectionStartedAt>",
  "completedAtUtc": "<actual successful handoff completion>"
}
```

Use actual objects, numbers, identifiers and UTC times. PASS must precede packet
staging and native disclosure; completed disclosure precedes final judgments.
The protected report and immutable review12 seal bind the complete envelope and
all three receipt digests. Attestation compares the protected original capture
index/preparation and installed validator blobs. This is controlled-route
provenance, not cryptographic proof of a human identity or absence of independent
source browsing; actual fresh-context/exposure verification remains mandatory.

The seven explicit final judgments, all17 dimensions, B1/B2 findings, paired
witnesses, functional/accessibility/privacy and technical evidence remain
required. Counts are preparations25/next26, reviews11/next12 and iteration16;
all original expiry, failures, authority caps and downstream ownership remain.

## Contract and impact

Extend `experience` on the owning `testing/contracts.json` entry. It declares
persona, objective, visible outcome, one integration owner, systems, source and
projection paths, entry, states, devices, roles, navigation, accessible fallback,
design target, accepted references, limitations and semantic visible-control
journeys. Cross-project contracts require observed continuity attributes.
Motion contracts require normal/reduced contexts and an explicit feedback
measurement boundary with a justified budget; use Lanternwake's presentation
authority. Fixture profiles reuse existing Sounding Line provisioning.
Named generic, Harborlight, Homeport Phase 3 and Lanternwake suite profiles are
supported, including their preparers and readonly setup. Dedicated Admiralty
journey runners need an experience adapter and fail explicitly with
`PROFILE_ADAPTER_REQUIRED`; selecting their name does not claim fixture proof.
Non-anonymous roles require a rendered identity/role witness after isolated
setup. Cross-project continuity is observed at the consumer outcome and after
return, and compared across device/role contexts for the same journey.

The protected-base registry determines mandatory policy. Candidate declarations
may add obligations, never erase or weaken existing journeys or grant debt.
Reverse imports, HTTP consumers, assets and both source graphs select complete
affected journeys. Global tokens/styles broaden coverage. Unresolved consumers
fail closed. Documentation, internal tooling and backend work with no user-facing
consumer keep their ordinary proof without visual overhead. Unknown UI requires
a design contract. The four spatial `experienceIntent` records select the
integration objective and fail until the task supplies a complete design;
they do not pretend those older experiences already meet that design.

Homeport screen/journey IDs and Brightwork's curated reference paths are checked
against protected registries. Reference screenshots are verified actual PNGs.
Historical acceptance supplies a design reference, not current product acceptance.
Deepwater's realization ladder remains meaningful: service success and persisted
role assignment cannot substitute for the promised accessible frontend.

## Capture, critique, repair and submission

1. Run `npm run experience:plan -- --base BASE --candidate SHA --plan true`.
   Define the objective and state/transition design before implementation.
2. Validate locally in an owned runtime. `npm run experience:capture -- --base
BASE --candidate SHA --url LOOPBACK --output
Development_Docs/Testing/Product_Experience/evidence` captures the actual app.
   Use the existing isolated browser fixture, never a shared server/database.
3. On a stable draft PR, dispatch the existing `sounding-line-ordinary.yml`
   workflow **on main**, with exact `base_sha`, `candidate_sha`, `candidate_ref`,
   `pr_number`, and `experience_mode=capture`. Preparation builds and runs the
   real candidate with its task-owned fixture. Download the immutable capture
   artifact and preserve its relative evidence paths. It contains the bounded
   reviewer packet, screenshots, videos, traces and observed journeys.
4. Give a separate reviewer the contract, objective, references and artifacts,
   excluding builder rationale. It inspects the experience before source and
   records concrete judgments for all 17 dimensions. Findings use the executable
   severity vocabulary. Confirmed blocking defects require repair, new captures
   and re-review. `repairDisposition` caps this at three iterations or no progress.
   Never hide a control or downgrade a promise to satisfy the gate.
5. Commit `candidate-review.json` and the actual reviewed artifacts. Set
   `captureArtifactId`; keep `ownerAcceptance=NOT_CLAIMED`. The report contains
   packet digest, contexts, dimensions, findings, iterations and observed results.
   Dispatch `experience_mode=review` on the same protected base. The trusted
   helper validates actual evidence and its capture provenance, then preserves
   the authenticated review submission as an immutable review artifact. Add its
   `reviewArtifactId` to the report without changing product source.
6. Freeze and make the PR ready. Ordinary Sounding Line validates artifact bytes,
   source/contract digests, protected capture/review provenance, semantic outcomes,
   roles/devices/motion, accessibility, return/continuity and blocking findings.
   It replays the actual candidate journeys. Missing mandatory evidence fails
   before expensive product verification. Preparation never supplies the required
   mainline decision and cannot bypass branch protection.

Workflow review submission is authenticated to the trusted actor list (initially
the repository owner account), and records the separate agent context honestly.
It is technical review attestation, not cryptographic proof of an AI identity or
KG's product acceptance. The automation may submit the authorized work; routine
owner babysitting is unnecessary. Expired artifacts require recapture/re-review.
Tokens stay in the trusted helper and are stripped from candidate child processes.

For activation only, `experience_diagnostic=true` exercises the representative
account contract even on unchanged main. `capture`, `review`, then `verify` modes
prove installed behavior and evidence trust without issuing a PR acceptance.
An `evidence_ref` may supply records for diagnostic review/verification; the
product identity is still calculated from the exact candidate. Ordinary PRs use
only their committed report.
