## Current-main cross-cutting failure

The generic `createRelease` → `preflightCommunityPublication` / `persistVerifiedCommunityPackage` → `installVerifiedCommunityPackage` path is not an authoritative Creator publishing journey. It does not derive a package from the saved source, bind package bytes to its immutable version, verify the submitted license against policy and included rights, or materialize a private second-Creator target before recording installation. Creator-owned publication transitions do not supply independent moderation. Homeport's detail explicitly states no accepted install/remix handoff. This generic path must not bypass the dedicated spatial or new Creator gates.

## SC-07 candidate scope and proof state

The independent candidate adds server-derived package, rights acknowledgment, moderation, and private installation routes for dependency-free `CHRONICLE`, `CHRONICLE_TEMPLATE` and `STORY_BLOCK_PRESET`. A Chronicle source requires the exact current `PublishedTaleVersion` and Drydock evidence; its Community package excludes media, artifacts, locations, Landfall, and external ID dependencies until their bytes and rights have a verified install path. Reusable items require an owner-scoped current saved version without external dependencies or inherited redistribution. Non-reusable future types remain unsupported.

The candidate closes the generic bypass: caller-supplied release, package, and install finalization endpoints now fail closed, while dedicated Creator routes derive the exact package from the owner-scoped saved source. The owner reviews the source, license, rights, credits, and full included content before submission. A distinct assured moderator reviews the same pinned package and ownership declaration before public release. Public listing detail exposes safe metadata and license terms, and a second Creator installs a private, credited copy pinned to the approved release. Chapter templates and Passage presets return to the existing private reusable Library; a dependency-free Chronicle returns to a private Studio fork. Sources with unverified media, spatial, artifact, location, or provider dependencies are refused. Existing `GUIDE` and `VOYAGE_LOG` restrictions and future unsupported types are unchanged.

Local development proof on the isolated `validation-isolated-sc07-20261031.db`: focused Vitest for preset, chapter template, Chronicle, and generic bypass passed (4 files, 6 tests); the preset browser journey passed (3 tests) across Creator package review, privileged moderator approval, public install, second-Creator Studio return, mobile installed return, and signed-out mobile fallback. The matching screenshots and owner/moderator/installer videos are in `Development_Docs/Testing/Product_Experience/evidence/sc07-community-local-20261031/`. The installed-item capture now shows the second Creator's owner-scoped private copy, original credit, release ID, and package checksum. Owner, moderator, public, and private screens use the same Passage preset and license display names. The Chronicle integration uses a synthetic immutable Drydock evidence row to exercise Harborlight's exact-source gate; it does not claim Drydock certification. Local production build, TypeScript, and targeted lint passed on the candidate. These receipts are not protected Sounding Line, SC-07A reconciliation, or landed-tree acceptance.

The Chronicle fork uses the existing Studio `forkPublishedVersion` service before its Community receipt transaction. A failed receipt commit compensates by removing that fork, but abrupt process termination between these steps can leave a private fork without a Community installation receipt. This limitation must be resolved or explicitly held before claiming complete Chronicle acceptance; the reusable-item installation is atomic within one database transaction.

Independent media-first Product Experience re-review examined all seven replacement screenshots and three role recordings. It closed the original private-return and terminology findings for the isolated synthetic journey: the installed private item visibly carries the same release ID and package checksum as moderation, plus the creator credit and license. The review retained bounded evidence limits: white/scaled opening video frames do not establish loading timing; keyboard traversal, measured contrast, actual mobile owner/moderator operation, stale-source recovery, and protected or real-account acceptance remain unproven. The long moderator detail layout and dense raw package view remain usability concerns, without a new confirmed blocker in the captured journey.
