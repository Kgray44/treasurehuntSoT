# Project Trim Phase 0 Baseline Audit

## 1. Executive summary

This bounded survey found a strong reuse substrate but no task-level Codex token
telemetry. The principal reducible cost is therefore not proven token volume; it
is repeated discovery across a large engineering-record corpus and broad,
heterogeneous machine-readable data. The first high-return change is a small,
generated Minimum Sufficient Context Packet (MSCP) that starts from changed
paths, ownership, contracts, suites, authority, and an accepted-status capsule.
It must permit automatic targeted expansion and must record that expansion.

The repository already has 475 contracts, 156 path mappings, 456 contract
mappings, 61 suites, 16 owners, 19 resources, seven release gates, a current
authority index, and a 1,049-record document index. Project Trim should compose
those sources; it should not duplicate them.

## 3. Measurement method

The survey used four representative repository increments and only their
readily available commit, record, instruction, index, and machine-manifest
evidence. It did not replay tasks, inspect whole conversations, install tools,
or run application, browser, or Sounding Line validation.

Evidence labels mean: **EXACT** for Git/object and file counts; **DIRECT_PROXY**
for stored configuration or records that show available context surfaces;
**ESTIMATE** for a bounded inference explicitly identified as such; and
**UNAVAILABLE** for telemetry not exposed safely by the sampled sources.

## 4. Measurement limitations

Exact input, cached-input, output-token, elapsed-time, prompt-size, file-read,
file-reread, search, and subagent-launch counts are
`UNAVAILABLE_FROM_CURRENT_EVIDENCE`. The local `.codex` configuration records
archive behavior and a maximum of three agent threads, but no task-level usage
counters. Full archived conversation contents were deliberately not mined.

The sample therefore characterizes context opportunities, not individual-token
attribution. “Likely” current paths in the MSCP example are estimates, not a
claim that a particular historical task opened every named file.

## 6. Token and context evidence

Exact token telemetry is **UNAVAILABLE**. Direct proxies show a small permanent
instruction core (the root instruction plus five active `.agents` files total
6,655 bytes; the mandatory testing workflow is 3,496 bytes) and a substantially
larger discovery surface: 1,474 engineering-record files (about 368 MB), 120
Sounding Line program files (about 37.6 MB), and 18 testing JSON files (about
566 KB). Those totals are not token estimates; they establish why unbounded
file discovery has a meaningful cost opportunity.

## 7. Repository archaeology findings

The repository contains authoritative facts, but they are distributed between a
1,049-record document index and multiple program trees. The four increment
classes differ sharply in required closure. A source-first search followed by
manual location of owner, contract, suite, prior status, and governing material
is therefore a recurring risk. The repair sample also had no returned direct
path-mapping entry for `src/components/studio/TaleEditor.tsx` in the inspected
impact map; a packet must expose that mapping gap and safely fall back rather
than silently assume coverage.

Replacement mechanism: resolve changed paths against the existing impact and
ownership maps, then attach only the resulting paths plus an explicit
`UNKNOWN_REQUIRES_EXPANSION` item where mapping is absent.

## 8. Governing-document reread findings

`AGENTS.md` requires every task to read `.agents/testing-workflow.md`; this is
an observed repository rule, not inferred task behavior. The effective
authority is an 88-line human projection backed by a machine index. Reopening
those concise sources is ordinarily justified. Reopening large amendment PDFs
or a full historical governing library for a focused repair is not established
as necessary by this survey.

Replacement mechanism: an authority slice containing authority version,
applicable policy IDs, required validation mode, and links to deeper authority.
The slice must never prevent a task from opening the primary material when the
task or an ambiguity requires it.

## 9. Prompt duplication findings

No safe prompt corpus or prompt-size metadata was available, so duplicated
permanent instructions are **UNAVAILABLE_FROM_CURRENT_EVIDENCE**. The durable
rules already reside in `AGENTS.md` and `.agents/`; a Phase 1 pointer/profile
can reference them rather than reproducing them in generated packets. This is a
design opportunity, not a measured historical saving.

## 10. Prior-phase reconstruction findings

The Deepwater candidate freeze and retained Phase 4 integration record show a
closure task spanning 14 changed files and multiple evidence/status artifacts.
The record binds candidate, merge, authority, protected-binding, and exact-main
identities. This is direct evidence that a compact accepted-phase capsule can
replace rediscovery of settled identities. It does not show how many historical
files any prior operator read.

## 11. Repeated-read findings

The mandatory instruction read is the only repeated read directly established.
The 1,049-record document index and program-scale inventories make repeated
status/ownership rediscovery plausible, but historical reread counts are
**UNAVAILABLE**. Phase 1 should add a per-task read ledger with file blob ID,
purpose, and whether the blob was already supplied; unchanged content can then
be measured without treating legitimate rereads as waste.

## 12. Subagent multiplication findings

The local configuration permits up to three agent threads (`max_threads = 3`),
but sampled task-level launch and inherited-context counts are unavailable.
Project Trim must slice subagent context by assigned closure and share packet
identities, rather than copying a parent’s broad discovery set. This is a
preventive requirement, not a measured multiplier.

## 13. Reporting and documentation output findings

The Deepwater freeze changed evidence, status, catalog, and index material;
the retained integration record is 3,293 bytes. Such durable evidence is
valuable and should not be removed. The avoidable candidate is duplicate
narration: reports should link to immutable packet, status-capsule, and
validation identities instead of restating their contents. Historical final
response sizes are unavailable.

## 15. Minimum Sufficient Context Packet feasibility example

Worked example: `eaaf46dac`, the Studio validation-field focus repair.

| Current likely context path (ESTIMATE) | Proposed initial packet |
| --- | --- |
| Read permanent instructions; locate the component and direct test; search for Studio ownership/contract material; check authority; investigate remount/focus behavior; then choose focused validation. | **Identity:** commit/base and changed path. **Scope:** defer focus one paint for remounted inspector fields. **Authority:** testing workflow plus v1.4 focused-repair rule. **Source roots:** `src/components/studio/TaleEditor.tsx`, its direct test, and inspector-field producer if needed. **Mappings:** no direct inspected impact-map entry; mark expansion required. **Tests:** direct component test first, then mapped/fallback closure. **Boundary:** no schema, migration, or cross-product change is indicated by the diff. **Risk:** asynchronous focus timing and cleanup. **Completion contract:** direct regression proof, then governed candidate qualification as applicable. |

The proposed packet starts with about 5–8 pointers rather than a program-wide
search. The exact historical number of avoided files, documents, searches, or
tokens is **UNAVAILABLE**; the packet is a feasibility design, not a savings
claim.

## 16. Autonomous progressive expansion requirements

Project Trim must define both `STANDARD_AUTONOMOUS` and
`UNATTENDED_CONTINUATION`. Both permit autonomous, targeted context expansion.
`UNATTENDED_CONTINUATION` continues through locally attainable work when more
context, local setup, a focused failure, or an independently blocked lane is
encountered. The governing principle is:

> CONTEXT EXPANSION IS NOT SCOPE EXPANSION.

Hard stops remain authorization, destructive action, unavailable credentials,
irreconcilable governance, unrelated-work risk, or no safe path—not ordinary
need for additional in-scope evidence.

## 17. Initial context budget recommendations

Until telemetry exists, use count and size guardrails rather than token claims:

- focused repair: 3–6 initial file pointers, one authority slice, and no more
  than one status capsule;
- bounded implementation: 6–12 pointers, up to two authority slices, one
  owner/contract/suite closure, and a main-delta summary;
- continuation/closure: add one accepted-phase capsule instead of a phase
  record sweep;
- record-only documentation: record identity, authority slice, documentation
  index obligation, and exact changed-path class only.

Each profile must carry expansion triggers, a blob-aware read ledger, and an
explicit conservative fallback for unmapped paths.

## 18. Ranked Phase 1 priorities

1. **MSCP generator with source, authority, and status slices** — Impact:
   HIGH; Effort: MEDIUM; Dependency: reuse existing JSON/index sources;
   mechanism: replaces broad discovery; Risk: stale or incomplete mapping,
   mitigated by fail-open targeted expansion and conservative fallback.
2. **Accepted phase capsule and main-delta identity** — Impact: HIGH; Effort:
   SMALL; Dependency: existing integration/evidence records; mechanism: avoids
   closure archaeology; Risk: incorrectly treating a partial phase as accepted.
3. **Read/context ledger with blob IDs** — Impact: MEDIUM; Effort: MEDIUM;
   Dependency: packet identities; mechanism: makes repeat-read and expansion
   cost measurable; Risk: telemetry overhead or privacy leakage.
4. **Context profiles plus `STANDARD_AUTONOMOUS` / `UNATTENDED_CONTINUATION`**
   — Impact: MEDIUM; Effort: SMALL; Dependency: packet contract; mechanism:
   removes repeated orchestration text while retaining autonomous expansion;
   Risk: profiles becoming a gate on needed context.
5. **Subagent packet slicing** — Impact: MEDIUM; Effort: MEDIUM; Dependency:
   packet and ledger; mechanism: limits duplicated parent discovery; Risk:
   omitted cross-lane dependency.

## 19. Expected measurable outcomes

Phase 1 should make the following measurable without inventing historical
baselines: initial-packet bytes/pointers; expansions and reasons; unique versus
repeat blob reads; mapping-fallback rate; authority/status capsule reuse;
subagent shared versus unique context; and final-report bytes that link rather
than restate. The first comparable post-implementation sample can establish
token/input/output metrics only if the runtime exposes them safely.
