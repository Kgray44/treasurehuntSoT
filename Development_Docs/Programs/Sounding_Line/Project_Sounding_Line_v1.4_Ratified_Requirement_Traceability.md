## Final frozen policy statements

- Evidence dispositions are exactly `FRESH`, `PRESERVED`, `REBOUND`, `INVALIDATED`, `SUPERSEDED`, and `CONSERVATIVE_FALLBACK`. Failure codes remain separate from dispositions.
- Closure confidence is exactly `EXACT`, `BOUNDED`, `COARSE`, or `UNKNOWN`. Only `EXACT` and explicitly bounded `BOUNDED` closure is preservation-eligible; `COARSE` records debt and `UNKNOWN` requires conservative expansion.
- Ordinary mainline MSES is fresh sentinels + semantic impact + base-movement invalidation + dependency-selected cross-project evidence + missing evidence + runtime/workspace conformance + exact candidate/train/tree binding. Unknown/debt requires a sealed conservative fallback and debt owner.
- The amendment intentionally freezes a sentinel _selection rule_, not hard-coded suite IDs: a small, explicit, machine-readable registry selects Sounding Line conformance when executable/authority source changes; core static/type/policy per policy; access/navigation for global user-facing executable impact; production build for executable/build impact and not record-only work. Prompt 3 must implement that registry; Prompt 2 must not guess IDs.
- Release-candidate remains independently exhaustive under release policy. Record-only closure is narrow integrity evidence; focused repair is nonauthoritative; emergency serial/current-base fallback is governed and cannot reuse stale evidence.
- Mapping debt is never a safe omission: affected `UNKNOWN`/unprotected debt expands the governed scope, attaches a debt record, and prevents fine-grained omission. Release-candidate cannot accept an unresolved mandatory obligation.
