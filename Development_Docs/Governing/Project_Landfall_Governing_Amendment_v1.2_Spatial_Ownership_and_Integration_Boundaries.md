# PROJECT LANDFALL v1.2 AMENDMENT

## Spatial Ownership, Sextant Migration, Parallax/Crossdeck Integration, and Device Lab Promotion

> **Governing Principle**  
> Landfall remains the authoritative system for world, place, route, region, waypoint, journey, and navigation truth. It may consume device context, spatial reality, visual evidence, and surface availability, but it must not re-create the systems that own those truths. Accepted Landfall behavior remains valid; this amendment changes future ownership and integration boundaries, not history.

This amendment is intentionally post-closure. Project Landfall completed its governed implementation program on protected `main` before Project Sextant, Project Parallax, and Project Crossdeck received their own canonical governing baselines. The correct response is not to reopen Landfall, rename accepted Phase 4 work, or pretend its native/device work never happened. The correct response is to preserve accepted behavior while formally establishing how that behavior participates in the newer Spatial Experience Architecture.

The amendment therefore performs five jobs:

1. preserves every accepted Landfall v1.0/v1.1 behavior and Phase 1–4 closure claim within its proven scope;
2. transfers **generic device-capability ownership** to Project Sextant while keeping accepted Landfall acquisition paths as compatibility seams until migrated;
3. transfers **spatial/AR ownership** to Project Parallax and **multi-surface ownership** to Project Crossdeck;
4. promotes the historical **Landfall Device Lab** into the platform-wide **Voyagewright Device Lab** governed by Project Sounding Line, with Landfall retaining a scenario pack rather than a private laboratory;
5. freezes the typed integration contracts through which Landfall will serve Storytide, Parallax, Crossdeck, Watchglass, Wakebook, Drydock, and future spatial systems.

No new Landfall implementation phase is created by this amendment.

3. **Adjacent-project implementation** — work owned elsewhere that consumes Landfall contracts.
4. **New Landfall product capability** — only if a genuinely new world/navigation requirement appears and receives explicit governance.

None of those silently creates “Landfall Phase 5.”

# 4. The Four Truth Domains

The spatial architecture must remain understandable enough that engineers can answer “who owns this?” without convening a tribunal.

## 4.1 Sextant: device truth

Sextant answers:

> What can this device sense or do, what observation is available, and how trustworthy/fresh/permitted is it?

Examples:

- heading estimate;
- orientation/attitude;
- motion state;
- magnetic anomaly;
- pressure/relative elevation;
- haptic capability;
- camera capability declaration;
- BLE/UWB/NFC availability;
- lifecycle/power/thermal state.

## 4.2 Landfall: world truth

Landfall answers:

> What does the current evidence mean in the Chronicle's world and journey?

Examples:

- Player is likely inside region A;
- active route segment is B → C;
- expected objective bearing is 247°;
- relative elevation is consistent with reaching upper-gallery context;
- virtual position is on island X;
- this chart viewport represents the current safe Player projection.

## 4.3 Parallax: spatial truth

Parallax answers:

> What authored spatial thing exists around the Player and where is it anchored/staged?

Examples:

- map is anchored on this desk;
- note is adaptively staged beside this chair;
- crew shares anchor `SA-123`;
- object is handheld versus placed;
- Chronicle Lens is rendering a trail.

## 4.4 Crossdeck: surface truth

Crossdeck answers:

> Which authorized surfaces are participating, what roles do they have, and how is presentation/custody synchronized?

Examples:

- desktop is primary story surface;
- phone is Chronicle Lens;
- map presentation moved desktop → phone;
- tablet is a crew-shared chart surface.

These domains may collaborate. They MUST NOT collapse into each other.

# 5. Generic Device Acquisition Migration to Sextant

## 5.1 Migration objective

The long-term target is:

```text
OS / Browser hardware APIs
          ↓
       SEXTANT
 semantic device context
          ↓
       LANDFALL
 world/navigation meaning
```

not:

```text
Landfall calls every mobile hardware API forever
```

## 5.2 Preserve accepted adapters during transition

Current accepted Landfall adapters may remain in source while Sextant is unimplemented or while migration is incomplete.

They must be treated as:

- compatibility providers;
- migration inputs;
- acceptance-preserved behavior;
- not precedent for adding additional generic hardware logic to Landfall.

## 5.3 No big-bang rewrite

Migration SHOULD happen capability family by capability family.

Example:

```text
current Landfall heading acquisition
        ↓
wrap/normalize behind Sextant heading contract
        ↓
Landfall consumes Sextant HeadingEstimate
        ↓
old direct acquisition retired only after parity proof
```

The same pattern applies to:

- orientation/motion;
- barometer/elevation raw context;
- generic BLE/UWB/NFC capability;
- lifecycle/power/thermal state;
- haptics if Landfall directly invokes them.

## 5.4 No double listeners

During migration, a capability must not remain actively acquired by both Sextant and Landfall without an explicit transition design.

Duplicate OS listeners can cause:

- battery waste;
- inconsistent calibration;
- conflicting sampling rates;
- duplicate permission prompts;
- race conditions;
- contradictory observations.

Sextant should become the canonical generic device observer, with Landfall subscribing to semantic outputs.

## 5.5 Position seam

Position requires careful division.

Sextant may own the **generic device position observation seam**: capability availability, permission/lifecycle, raw observation envelope, accuracy/freshness/provenance.

Landfall owns **geospatial interpretation**: map coordinates, Worldspace transform, route matching, region membership, location privacy policy, arrival confidence, journey semantics, offline map meaning, and completion-provider context.

Sextant never decides “the Player arrived at waypoint 7.”

## 6.1 Confidence composition

Landfall MUST NOT copy Sextant confidence and relabel it as arrival confidence.

For example:

```text
Sextant heading quality: HIGH
```

does not imply:

```text
Landfall target alignment: HIGH
```

Landfall computes world-specific meaning using:

- authored geometry;
- route topology;
- Worldspace coordinate reference;
- Sextant observations;
- Landfall provider evidence;
- freshness/correlation policy;
- optional Watchglass evidence where governed.

## 6.2 Permission copy

Landfall may explain why a navigation feature benefits from a capability, but Sextant owns generic device permission state/purpose binding once the capability has migrated.

Do not create separate Landfall and Sextant permission prompts for the same hardware capability.

# 7. Parallax Integration Boundary

Landfall and Parallax are complementary, not hierarchical.

Landfall knows **where the journey is in a world**.

Parallax knows **where a spatial entity exists relative to the Player/environment**.

## 7.1 Landfall provides context, not anchors

Landfall may provide Parallax with:

- active `worldspaceId`;
- safe current region/site/floor context;
- active route segment;
- objective waypoint/place reference;
- expected bearing to authored target;
- worldspace transform metadata;
- virtual-world position;
- safe journey/path context;
- map/chart viewport reference;
- contextual precision class;
- location confidence/quality;
- relevant offline/availability state.

Landfall MUST NOT create:

- ARKit/ARCore world anchors;
- room-local plane anchors;
- semantic adaptive anchors;
- shared AR anchor identities;
- spatial meshes;
- Parallax scene graphs.

## 7.2 Parallax may request world eligibility

A Spatial Moment may ask Landfall:

> Is this Player currently inside the world/region context where this spatial experience is allowed to resolve?

Landfall can answer with a bounded context projection such as:

```text
WorldEligibility
  worldspaceId
  regionId?
  eligible: true
  confidence: MEDIUM
  precisionClass: SITE
  expiresAt
```

Parallax then decides where/how to stage the spatial entity.

## 7.3 Geospatial anchors

If Parallax supports Earth/geospatial anchors, Landfall supplies canonical Worldspace/place references; Parallax owns the spatial anchor representation/render lifecycle.

A geospatial AR anchor does not become a second Landfall waypoint.

## 7.4 Adaptive room experiences

An adaptive private-room Chronicle may require no Landfall geography at all. Parallax can stage against local scene semantics while Landfall is absent.

That is valid architecture, not a Landfall failure.

# 8. Crossdeck Integration Boundary

Landfall owns chart/map/world state. Crossdeck owns where that presentation appears.

## 8.1 Safe chart reference

A chart moved between surfaces should carry a typed reference such as:

```text
LandfallChartViewReference
  worldspaceId
  mapDefinitionVersion
  voyageId
  viewport
  activeRouteId?
  objectivePlaceId?
  visibilityProjectionVersion
  generatedAt
```

The destination surface resolves the canonical Landfall data through authorized services.

It should not receive an independent mutable clone of the map domain.

## 8.2 Surface-specific presentation

Crossdeck may choose:

- desktop for large Living Chart;
- phone for compact compass/navigation;
- tablet for a shared chart;
- headset for spatial overlay.

Landfall remains the data/meaning owner across them.

## 8.3 Handoff does not equal progression

Moving a map or navigation panel between surfaces changes presentation, not journey state.

If Storytide authors a transfer challenge, One Voyage remains the progression authority.

# 9. Watchglass Integration Boundary

Current protected Landfall includes limited authored-view appearance comparison and independent exact-object observation concepts. General Watchglass remains planned/not configured.

## 9.1 Compatibility rule

Accepted current Landfall visual/context evidence remains valid until Watchglass provides an accepted replacement contract.

Do not delete or relabel accepted Landfall Phase 3 evidence merely because Watchglass is planned to become the long-term perception owner.

## 9.2 Future target

When Watchglass is implemented and certified:

```text
Camera / visual evidence
      ↓
   WATCHGLASS
 typed perception receipt
      ↓
    LANDFALL
 place/navigation interpretation
```

Examples:

- Watchglass: “recognized authored facade, 0.91 confidence, accepted pose volume.”
- Landfall: “recognition is consistent with region/waypoint context; completion provider may consider combined evidence.”

## 9.3 Abstention

Watchglass may abstain. Landfall must preserve:

- map guidance;
- location/route context;
- alternative completion;
- Captain recovery;
- accessibility fallback.

Visual recognition is never silently treated as infallible navigation truth.

## 9.4 No scene rendering

Watchglass does not render AR markers; Parallax does.

Landfall does not perform general object recognition; Watchglass does.

# 12. Device Lab Promotion

## 12.1 Historical fact

Landfall Phase 4 created and governed **The Landfall Device Lab** because Landfall was the first project to require serious mobile/device/lifecycle/provider simulation.

That work was correct and valuable.

## 12.2 New permanent authority

The Voyagewright Spatial Experience Architecture establishes:

> **Voyagewright Device Lab is shared platform verification infrastructure governed by Project Sounding Line.**

Therefore the old Landfall Device Lab is reclassified as the **founding Landfall scenario family and implementation provenance** of the platform-wide lab.

## 12.3 What remains Landfall-owned

Landfall owns its scenario semantics/assertions, such as:

- foreground physical-route arrival;
- background geofence/reconciliation;
- offline map region behavior;
- virtual Worldspace observation;
- route/provider outage;
- location privacy degradation;
- Landfall-native restart/reconciliation;
- Landfall field-navigation acceptance.

## 12.4 What moves to Sounding Line Device Lab

Shared lab ownership includes:

- common scenario schema;
- runner orchestration;
- device/emulator inventory;
- Android/iOS simulator provisioning;
- hosted macOS execution;
- evidence-tier definitions;
- shared capability injection;
- reusable lifecycle/network/power simulation;
- artifact/evidence storage;
- cross-project device resource scheduling;
- lab diagnostics and policy.

## 12.5 Command compatibility

Historical commands such as `landfall:device-lab` may remain as aliases or project-specific entry points if useful.

They MUST delegate to the shared Device Lab architecture once that platform interface exists.

A compatibility command is not ownership.

## 12.6 Evidence preservation

Historical Landfall Device Lab evidence retains its original classifications.

No evidence is upgraded merely because the lab is renamed/promoted.

`EMULATOR_PROVEN` does not become `REAL_DEVICE_PROVEN` by organizational decree. Tempting, certainly. Also nonsense.

# 14. Capability and Fallback Policy

Landfall may consume advanced capabilities without making them mandatory for ordinary world navigation.

Examples:

## Heading
Preferred: Sextant fused heading.  
Fallback: map orientation / route cue / textual bearing.

## Relative elevation
Preferred: Sextant pressure-fused relative elevation.  
Fallback: route topology / GPS elevation / authored floor confirmation / manual clue.

## UWB proximity
Preferred: Sextant UWB/ranging.  
Fallback: Landfall region + Watchglass/visual + manual confirmation.

## Spatial trail
Preferred: Parallax ground-anchored trail.  
Fallback: Landfall Living Chart route.

The zero-infrastructure rule survives every one of these extensions.

# 15. Privacy and Precision Boundaries

Landfall still owns:

- private geometry classification;

## 15.4 Watchglass camera evidence remains separate

# 16. Safety Boundary

Landfall remains the primary safety authority for physical navigation context.

Parallax may render an AR trail, but it must not override Landfall safety rules.

Examples:

- no AR objective placed across an unsafe crossing simply because tracking found a good plane;
- no “look through phone continuously” requirement while navigating traffic;
- no adaptive scene that draws a Player into a prohibited/private region;
- no Storytide hint that contradicts a Landfall safety closure;
- no Crossdeck handoff requiring risky device handling while walking.

When safety and spectacle conflict, safety wins. The ghost can wait.
