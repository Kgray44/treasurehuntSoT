## Authoring authority

Creators submit intentional natural-language requests. OpenAI Responses uses strict structured outputs; model output is untrusted advisory data. One versioned proposal binds request, draft identity, exact scene state and revision. An allowlist maps supported entity creation, content, transform, placement, visibility, interactions, behavior timeline and accessibility changes through ordinary reversible authoring semantics. Server checks cover ownership, references, locks, dependencies, spatial constraints and deterministic materialization. Unsupported effects receive a truthful finding or supported alternative. Ambiguity receives a short clarification. No executable code, external tools, provider-selected URL, direct database edit or progression command is permitted.

Review presents semantic change cards and an actual scene preview before application. Independent selected changes must include their declared dependencies; bundles apply atomically. Stale state cannot overwrite newer work. Application enters ordinary history, autosave, undo/redo, Drydock and immutable library/Chronicle attachment flows. Published definitions remain immutable. Manual editing remains available with AI disabled.

## Provider and privacy

Local Windows development uses the shared user-level `OPENAI_API_KEY`, read only through the server process environment. No worktree requires a credential file. Safe diagnostics disclose configuration booleans, never the credential. Cloud Personal Vault remains a separate environment. Per-user AI usage and exceptions belong in the existing Admiralty account dossier reached through People search; the global AI Usage & Quotas console does not add a second account search.

OpenAI is the primary live provider, with `gpt-6-luna` standard and explicitly authorized `gpt-6.1-sol` advanced. Advanced never activates automatically. Reasoning, models, token bounds, timeout and versioned pricing are typed policy. Only a fixed allowlisted upstream is contacted; server credentials never reach clients or diagnostic projections. Existing HTTPS adapter compatibility uses the same governed admission and accounting interface, and fails closed without defensible pricing. No SDK is presently installed; use the documented Responses REST contract unless a justified SDK dependency is added.

Send bounded selected/nearby geometry, safe identities, capability contracts and relevant finding codes. Omit Chronicle text, clue answers, assets, calibration media, other users' data and unrelated content. Treat labels and imported descriptions as data, never instruction authority. Bound task context by account and draft with retention; fresh sessions rebuild from canonical state. Logs and ordinary usage reports contain safe metadata, never prompts or scene content.

## Durable quota authority

Parallax owns persistent provider policy, versioned prices, global/user policy revisions, UTC monthly periods, reservations and settlement records. Admiralty exposes discoverable AI Usage & Quotas through existing privileged capability and command ports. All changes require CSRF, recent assurance, explicit preview/confirmation, revision checks, bounded inputs, idempotency and transactional audit receipts. Support access grants cannot change spending policy.

Initial live AI and advanced access are disabled. Default monthly limits are 500 requests per user, 10,000 globally and $10 globally, with a $5 warning. Rate limits are 10/user and 60/global per minute; concurrency is 1/user and 3/global. Administrators may edit safe model/token/rate/concurrency/request/cost/retention policy, suspend users, restore inheritance or grant expiring overrides. Global hard limits constrain every user override. Historical usage is never reset or erased to create budget.

Use integer money at sub-cent precision. Before dispatch, atomically evaluate and reserve user/global monthly requests, money, rate and concurrency in one authoritative database transaction. Concurrent servers share that state. Settlement uses the reservation's immutable pricing revision and provider usage, including relevant cached input/cache writes and reasoning within output. Release only defensibly unused capacity. Unknown accepted usage remains conservatively charged pending reconciliation; crashes, cancellation, month rollover and retries cannot duplicate dispatch or erase spending. No automatic paid retry. Record estimated versus settled usage honestly. Dedicated upstream project spending controls are a secondary defense whose actual provider semantics must be verified and documented.
