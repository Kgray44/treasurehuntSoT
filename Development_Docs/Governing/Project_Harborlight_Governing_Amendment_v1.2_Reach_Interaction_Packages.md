# Project Harborlight v1.2 — Reach Interaction Packages

## 1. Authority and content boundary

This extends [Harborlight v1.1](Project_Harborlight_Governing_Amendment_v1.1_Spatial_Content_Distribution_and_Compatibility.md). Harborlight owns immutable content distribution and compatibility, not interaction recognition or device calibration. The new Reach definition family follows existing package integrity and edition rules.

## 2. Allowed distributed content

Packages may include versioned approved interaction definitions, semantic target references, permitted operations, constraints, conventional alternatives, explanatory assets and approved public model references/assets where licensing and delivery policy permit. Definitions are declarative and cannot execute arbitrary camera code or override Reach safety thresholds.

Private calibration parameters, raw camera footage, user hand tracks, protected Device Lab evidence, room imagery and runtime session tokens are prohibited from ordinary Community packages. A model asset digest identifies public software; a calibration fingerprint remains private runtime context.

## 3. Compatibility resolution

Declare Reach definition version and required/preferred interaction capability separately from camera support. Receiver/browser compatibility must distinguish supported but unqualified, unavailable, optional with fallback and essential without fallback. Model/provider upgrades do not silently change published puzzle semantics.

Drydock validates essential alternatives and owner-domain completion rules before publication. Harborlight distributes accepted definitions and manifests; it does not certify physical accuracy or promise that every browser backend works. Unsupported optional gesture presentation degrades to the declared conventional path.

## 4. Acceptance and future implementation

Package tests must reject private calibration/footage, unknown operation/schema versions, injected executable handlers and missing integrity/license metadata. Compatibility tests exercise fallback and edition binding. Reach runtime data never enters package caches as shared content. This amendment governs future package support without claiming it is implemented.

## Publication and implementation boundary

This amendment is additive. Preserve the accepted baseline and all historical evidence. Its requirements become the effective documentation contract on protected-main acceptance; they do not claim new runtime implementation or passing physical qualification. Future work uses focused validation, the ordinary Sounding Line final check, protected-main integration, and a landed-tree smoke check. Sounding Line remains the software verification authority; One Voyage remains the progression authority.

The [Reach governing document](Project_Reach_Spatial_Interaction_and_Intent_System_Governing_Document_v1.0.md) defines the shared interaction contracts. The [effective spatial authority index](Voyagewright_Spatial_Experience_Effective_Authority.md) identifies the complete governing chain. Product implementation status remains explicit in the registries and project homes.
